# 第五版正式部署验证记录

## 1. 记录目的与边界

本文汇总 ExamForge 第五版在腾讯云正式环境取得的部署、运维、恢复、容量和回滚证据，供课程设计报告引用。它只记录已经完成且可追溯的验证，不以本地成功、单次 HTTP 响应或人工访问替代未执行的自动化验收。

- 正式运行版本为 `v5.0.5`，源提交为 `f12486160dcacc09c00f29b6ed63110f1f3378a9`。
- `v5.0.6` 是仅在本地提交并推送的源码修复，未生成 release manifest、未发布镜像，也未部署到服务器。
- 记录不包含服务器 IP、登录密码、Cookie、Token、环境文件内容、数据库转储或未脱敏日志。
- 自动 online smoke、正式域名四角色 Playwright 和真实有限开放观察没有执行，原因及边界见第 6 节；本文不将它们标记为通过。

## 3. 部署与运行安全验证

### 3.1 部署过程

部署入口先校验 release manifest 及其附件，再按精确 digest 拉取应用镜像、执行迁移并启动生产 Compose。部署完成后，7 个常驻容器 health 均通过，API、Publisher、Worker 和 Scheduler readiness 均通过，4 个应用容器的 OCI revision 与 `f124861` 一致。

生产 secrets 只保留在权限为 `600` 的环境文件中。发布目录不保存源码，应用不开放 PostgreSQL、Redis、Scheduler 或 Worker 的公网端口。`current` 与 `previous` 以原子切换维护，失败部署可恢复到上一份已验证 manifest。

### 3.2 HTTPS、反向代理与周期运维

| 验证项 | 结果 |
| --- | --- |
| HTTP 与 `www` 重定向 | 均单跳重定向到 `https://examforge.site`。 |
| 公网健康端点 | `/_health/api` 与 `/_health/api-ready` 返回 `200`。 |
| TLS 证书 | 证书覆盖主域和 `www`；`certbot renew --dry-run --cert-name examforge.site` 成功。 |
| nginx | `nginx -t` 通过；SSE 使用独立反向代理配置，关闭缓冲并设置长读取超时。 |
| 日志轮转 | nginx 独立日志规则 dry-run 通过，按日轮转并支持单文件达到 25 MB 时提前轮转。 |
| 周期任务 | 健康巡检与每日备份 systemd timer 均为 enabled/active；部署完成后的健康巡检成功执行已复核。 |

用户另行完成了人工浏览器登录和页面可用性检查。这是人工验收，不计为自动 Playwright 证据。

## 4. 数据保护、恢复与故障恢复证据

### 4.1 备份与恢复

生产 PostgreSQL 备份使用 custom format，并生成 dump、校验和、脱敏业务摘要和元数据 4 类附件。热备目录与 COS 副本逐字节一致；恢复目标必须同时满足命令确认、`_disposable` 命名和数据库级 disposable 标记，避免覆盖在线库。

切流后的备份已在可丢弃数据库中完成恢复、迁移检查和脱敏摘要比对，随后删除该临时恢复库。健康检查会继续验证本地和 COS 备份完整性及备份年龄。

### 4.2 内部远程故障与回滚闭环

在正式域名开放前，`a507993` 制品曾在同一腾讯云主机按 digest 完成内部远程验证。该轮证据用于证明运行恢复、备份恢复和回滚能力，不把它替代为正式域名 E2E。

| 场景 | 已验证结果 |
| --- | --- |
| 50、100、150 场固定 seed 排考 | 均得到 feasible 结果且硬冲突为 0。 |
| API、Redis、Publisher、Worker 故障 | 恢复后保持单一运行和连续事件链。 |
| Scheduler 冷恢复 | 连续 3 次 `scheduler_unavailable` 后第 4 次成功，最终为 1 个运行和 14 个有序事件。 |
| SSE 重连 | API 重启后通过 `Last-Event-ID` 只补发后续事件并收到成功终态。 |
| 跨版本回滚 | 回滚到 `f769725` 用时 127 秒，业务 smoke 通过；重新部署 `a507993` 用时 128 秒并再次通过 readiness 与业务 smoke。 |
| 内部资源观察 | 10 分 28 秒、20 个样本中没有 OOM、重启、不健康容器、错误日志增长或 swap 使用。 |

## 5. `v5.0.5` 正式部署后的稳定性观察

2026-07-24 20:26 至 20:56（CST）采集了部署后基线和 5 次完整样本。观察结果如下：

- 7 个容器始终为 `healthy`，重启计数为 0，OOM 标记为 false。
- 两个公开健康端点持续返回 `200`；全量健康检查及本地/COS 备份完整性检查通过。
- 可用内存位于 2177 至 2209 MiB，数据盘可用空间约为 19,306,532 KiB。
- nginx error log 行数保持为 12，应用服务错误关键字计数为 0。
- 部署转换瞬间的健康巡检曾记录 1 次失败，原因是服务重建；部署完成后的下一次巡检及全部观察样本均成功。

该观察证明部署后短时间内的运行稳定性，不代表真实有限开放流量，也不代表自动浏览器验收完成。

## 7. 可用于课程报告的结论

第五版已经证明了可追溯 digest 部署、HTTPS 反向代理、7 服务健康检查、异机备份与可丢弃库恢复、故障恢复、跨版本回滚、150 场固定基准和部署后稳定性观察。课程报告可将这些内容作为“部署与运维验证”材料，并应同时保留第 6 节的限制说明。

报告中不得写成“正式域名自动四角色 E2E、官方 online smoke 和真实有限开放观察均已通过”。这些验证尚未执行，后续是否运行取决于新的维护授权和独立当前凭据。
